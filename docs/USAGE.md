## Установка и запуск

Установка не нужна. Скачайте архив для своей системы со страницы
[релизов](https://github.com/Etr1x/kuma_log_sender/releases/latest), распакуйте его в любую
папку, куда у вас есть право записи, и запустите исполняемый файл:

| ОС | Архив | Запуск |
|---|---|---|
| Windows | `kuma_log_sender_<версия>_windows_amd64.zip` | двойной щелчок по `kuma_log_sender.exe` или запуск из PowerShell / cmd |
| Linux | `kuma_log_sender_<версия>_linux_amd64.tar.gz` | `./kuma_log_sender` в терминале |

В архиве один исполняемый файл без внешних зависимостей, пример конфига
`collectors.example.json`, примеры логов в `logs/examples` и документация.

Окно терминала должно быть не меньше **80×20** символов; удобнее 120×30 и больше. Размер
можно менять на ходу. Подходят Windows Terminal, обычная консоль Windows (conhost),
любые терминалы Linux, а также сеанс по SSH.

Рядом с программой появляются файлы `collectors.json`, `sender.log`, `state.json` и папка
`logs`. Если папка программы недоступна для записи или вы хотите хранить данные
отдельно, укажите рабочую папку: `kuma_log_sender --dir D:\kuma-test` (или переменная
окружения `KUMA_LOG_SENDER_HOME`).

## Экран программы

```text
 шапка: версия, хост по умолчанию, таймаут, рабочая папка
┌─ Коллекторы ────┐┌─ Источник (logs) ─┐┌─ Параметры ──────────────┐
│ куда отправлять ││ что отправлять    ││ как отправлять и итог    │
└─────────────────┘└───────────────────┘└──────────────────────────┘
┌─ Предпросмотр ───────────────────────────────────────────────────┐
│ события в том виде, в каком они будут отправлены                 │
└──────────────────────────────────────────────────────────────────┘
┌─ Задачи ─────────────────────────────────────────────────────────┐
│ идущие и завершённые отправки                                    │
└──────────────────────────────────────────────────────────────────┘
┌─ Журнал ─────────────────────────────────────────────────────────┐
│ результат каждой отправки                                        │
└──────────────────────────────────────────────────────────────────┘
 подсказка по клавишам для активной панели
```

Активная панель выделена цветом рамки. Между панелями переходят клавишами `Tab` и
`Shift+Tab` или стрелками `←` `→`, внутри панели — стрелками `↑` `↓`.

Главное правило: **`Enter` в любой панели отправляет выбранный источник на выбранный
коллектор с текущими параметрами.** Поэтому отправить тот же лог ещё раз — это одно
нажатие `Enter`, а отправить другой файл туда же — `↓` и `Enter`.

Выбор коллектора, файла и параметры запоминаются между запусками.

Горячие клавиши работают в любой раскладке: `e` и `у` — одна и та же клавиша.
Полный список клавиш открывается по `?`.

## Коллекторы

### Хост по умолчанию

Обычно все коллекторы работают на одном сервере, поэтому его адрес задаётся один раз:
нажмите `g` и заполните поле «Хост по умолчанию» (DNS-имя или IP-адрес, без `http://`
и порта). Там же задаётся таймаут — сколько секунд ждать подключения и ответа.

### Добавление и изменение

| Клавиша | Действие |
|---|---|
| `a` | добавить коллектор |
| `e` | изменить выбранный |
| `y` | создать копию выбранного (удобно для похожих коллекторов) |
| `d` | удалить выбранный (с подтверждением) |
| `/` | фильтр по имени, протоколу или порту |

В форме `↑` `↓` или `Tab` переходят между полями, `←` `→` или пробел меняют значение в
полях-переключателях, `Enter` сохраняет, `Esc` отменяет. Изменения сразу записываются в
`collectors.json`.

### Поля коллектора и откуда брать значения

Значения берутся из коннектора коллектора в веб-интерфейсе KUMA (ресурс коллектора,
шаг «Транспорт»).

| Поле в программе | Где смотреть в KUMA | Примечание |
|---|---|---|
| Имя | — | как вам удобно; должно быть уникальным |
| Протокол | тип коннектора | `tcp`, `udp` или `http` |
| Хост | адрес сервера коллектора | пусто — используется хост по умолчанию |
| Порт | поле «URL» коннектора (`:5144`) | число от 1 до 65535 |
| Разделитель | поле «Разделитель» | должен совпадать; см. ниже |
| TLS | «Режим TLS» на вкладке «Дополнительные параметры» | включите, если режим не «Выключено» |
| Проверять сертификат | — | обычно выключено: сертификаты коллекторов самоподписанные |
| Путь | — | только для http; у коннектора KUMA это `/input` |
| Описание | — | пометка для себя, показывается в панели параметров |

### Разделитель

Разделитель — это символ, которым коннектор отделяет одно событие от другого. Программа
дописывает его **после каждого события**. Значения те же, что в KUMA:

| Значение | Символ | Когда используется |
|---|---|---|
| `\n` | перевод строки | значение по умолчанию у tcp-коннектора; однострочные события |
| `\0` | нулевой байт | многострочные события (например, от агента KUMA по http) |
| `\t` | табуляция | редко |
| нет | ничего не дописывается | значение по умолчанию у udp- и http-коннектора: одна датаграмма или один запрос — одно событие |

Если в коннекторе разделитель не выбран, оставьте «нет». Если разделитель в программе и
в коннекторе не совпадает, события склеиваются или в них попадает лишний символ, из-за
чего нормализатор может их не разобрать.

## Источник: файлы и ручной ввод

### Файлы

В панели «Источник» перечислены все файлы из папки `logs`, включая вложенные папки.
Список обновляется сам раз в пару секунд — файл можно положить или поправить, не закрывая
программу; содержимое читается заново при каждой отправке. Клавиша `/` включает фильтр
по имени.

Файлы должны быть в кодировке UTF-8. Программа сама:

- убирает BOM;
- перекодирует UTF-16 (в такой кодировке сохраняет вывод `>` старый Windows PowerShell);
- заменяет переводы строк Windows (CRLF) на LF, чтобы в конец событий не попадал `\r`.

О снятии BOM и перекодировании сообщается в журнале и в заголовке предпросмотра.
В остальном содержимое передаётся байт в байт. Размер файла — до 256 МБ.

### Ручной ввод

Клавиша `i` открывает окно ввода. Текст можно набрать или вставить.

| Клавиша | Действие |
|---|---|
| `Enter` | отправить введённый текст |
| `Ctrl+J` | новая строка (также `Alt+Enter`, `Shift+Enter`, если их передаёт терминал) |
| `Tab` | символ табуляции (показывается стрелкой `→`) |
| `Ctrl+R` | очистить поле |
| `Esc` | закрыть окно, сохранив текст |

Введённый текст остаётся источником «ручной ввод» (первая строка в списке): `Enter` на
основном экране отправит его снова, а параметры (повторы, интервал, цикл) можно менять
между отправками.

**Вставка из буфера обмена на основном экране** сразу открывает окно ввода с вставленным
текстом — остаётся нажать `Enter`. В старой консоли Windows вставка выполняется правой
кнопкой мыши или `Ctrl+V`; перевод строки внутри вставленного текста отправку не
запускает.

В поле ввода помещается до 10 000 строк; большие наборы событий отправляйте из файла.

## Параметры отправки

| Параметр | Клавиша | Значения |
|---|---|---|
| Режим | `m` | построчно, целиком, по разделителю |
| Повторов | `c` — ввести, `+` `-` — изменить | от 1 |
| Интервал | `t` | пауза между отправками |
| Цикл | `l` | вкл / выкл |

Можно также перейти в панель «Параметры» (`Tab`), выбрать строку стрелками и менять её
пробелом, `+` и `-` или сразу набрать число.

### Режим

Режим определяет, как текст источника делится на события.

- **Построчно** — каждая непустая строка отправляется отдельным событием. Так
  проигрывается файл с несколькими логами: строка за строкой, с паузой «Интервал» между
  ними, и после каждой строки дописывается разделитель коллектора.
- **Целиком** — весь текст отправляется одним событием. Нужен для многострочных событий
  (XML, многострочный JSON). Пустые строки в конце отбрасываются.
- **По разделителю** — текст режется по символу-разделителю коллектора. Доступен, только
  если разделитель коллектора — `\0` или `\t`, и позволяет хранить в одном файле
  несколько многострочных событий, разделённых нулевым байтом.

В панели «Предпросмотр» всегда видно, сколько событий получится и как они выглядят;
перевод строки внутри события показан как `↵`, табуляция — как `→`.

### Повторы, интервал и цикл

Весь набор событий источника отправляется «Повторов» раз. Между любыми двумя отправками
выдерживается «Интервал». В панели параметров показан итог, например
`3 события × 2 = 6 отправок, ≈ 5s`.

Интервал вводится числом секунд (`1`, `0.5`) или с единицей (`500ms`, `2s`, `1m`).
`0` — без паузы. По умолчанию — 1 секунда.

При включённом цикле набор событий отправляется по кругу бесконечно, число повторов не
учитывается. Остановить — клавиша `s`.

## Отправка и задачи

`Enter` запускает **задачу** — отправку в фоне. Интерфейс при этом не блокируется: можно
выбрать другой коллектор или файл и запустить ещё одну задачу, пока идёт первая. Так
отправляются события на несколько коллекторов одновременно или держится фоновая
циклическая отправка, пока вы проверяете что-то другое.

В панели «Задачи» по каждой задаче показаны номер, состояние, коллектор и источник,
счётчик `отправлено/всего`, число ошибок и время до следующей отправки.

| Состояние | Значение |
|---|---|
| идёт | задача выполняется |
| готово | все события отправлены |
| готово (!) | отправлено, но были ошибки или предупреждения — смотрите журнал |
| остановлена | остановлена пользователем |
| ошибка | не удалось отправить ни одного события |

| Клавиша | Действие |
|---|---|
| `s` | остановить последнюю запущенную задачу; в панели «Задачи» — выбранную |
| `S` | остановить все задачи |
| `x` | убрать из списка завершённые задачи |

При выходе (`q`) программа спросит подтверждение, если есть работающие задачи.

## Журнал

Каждая отправка оставляет запись — на экране и в файле `sender.log` рядом с программой.

```text
10:15:02.101 INF #3 старт: файл auditd.log → «Linux Auditd» udp://kuma:5916 | событий: 5 (687 Б), повторов: 1, интервал: без паузы, разделитель: \n
10:15:02.102 OK  #3 [1/5] отправлено → udp://kuma:5916: 331 Б за <1 мс | type=SYSCALL msg=audit(1760264101.123:4242): …
10:15:07.250 ERR #4 [1/1] НЕ отправлено → tcp://kuma:5140: dial tcp …: connection refused — порт закрыт: коллектор не запущен, слушает другой порт или подключение отклоняет файрвол
```

| Метка | Значение |
|---|---|
| `OK` | событие передано: номер и общее число отправок, адрес, размер в байтах вместе с разделителем, время, для http — ответ сервера, начало события |
| `ERR` | событие **не** отправлено: текст ошибки и подсказка, что проверить |
| `WRN` | событие отправлено, но есть признаки, что оно не принято |
| `INF` | начало и итог задачи, установление соединения |

`#3` — номер задачи. На экране длинные записи об успешной отправке сокращаются до одной
строки; клавиша `w` включает полный показ с переносом. Ошибки всегда показываются
целиком. Журнал прокручивается в своей панели (`Tab` до «Журнала», затем `↑` `↓`,
`PgUp` `PgDn`; `End` — вернуться к последним записям). В `sender.log` всё пишется
полностью.

## Что именно уходит на коллектор

| Протокол | Как передаётся событие | Что означает `OK` |
|---|---|---|
| tcp | событие и разделитель записываются в соединение; одно соединение на задачу | соединение с коллектором установлено, данные в него записаны |
| udp | одна датаграмма = событие и разделитель | датаграмма отправлена; доставка не подтверждается |
| http | `POST` на `http(s)://хост:порт/путь`, тело = событие и разделитель | коллектор ответил кодом 2xx |

Особенности:

- **TCP.** Если сервер закрыл соединение между отправками, программа замечает это и
  переподключается; об этом будет запись в журнале.
- **UDP.** Подтверждения доставки в протоколе нет, поэтому итог нужно проверять в KUMA.
  Но если на удалённом хосте никто не слушает порт и хост отвечает ICMP-сообщением
  «порт недоступен», программа сообщит об этом предупреждением. Событие должно помещаться
  в одну датаграмму — не больше 65 507 байт.
- **HTTP.** Заголовок `Content-Type: text/plain`. Перенаправления не выполняются, системный
  прокси не используется.
- **TLS.** Поддерживаются TLS 1.2 и 1.3. Проверка сертификата сервера по умолчанию
  выключена, что соответствует режиму TLS «Включено» у коннектора.

## Типовые сценарии

### Проверить нормализатор одним событием

1. Скопируйте исходное событие в буфер обмена.
2. Выберите коллектор и вставьте событие в окно программы.
3. Нажмите `Enter` и найдите событие в KUMA.
4. Поправили нормализатор — снова `Enter`.

### Проиграть последовательность событий для правила корреляции

1. Запишите события в файл в папке `logs`, по одному в строке, в нужном порядке.
2. Выберите коллектор и этот файл, режим — «построчно».
3. Клавишей `t` задайте паузу между событиями, например `2`.
4. `Enter`. События уйдут по порядку с заданной паузой.

Если правило срабатывает на N одинаковых событий, достаточно одной строки и
`c` = N: событие уйдёт N раз с выбранным интервалом.

### Многострочное событие (http-коннектор с разделителем `\0`)

1. У коллектора в программе: протокол `http`, разделитель `\0`, TLS — как в коннекторе.
2. Положите событие в отдельный файл.
3. Переключите режим клавишей `m` на «целиком» — в предпросмотре должно быть 1 событие.
4. `Enter`. В журнале будет ответ коллектора, например `HTTP 200 OK`.

Дописывать нулевой байт в файл вручную не нужно — это делает программа. Если байт в конце
файла уже есть, второй раз он не добавится.

### События auditd

Когда у коннектора включён переключатель **Auditd**, он сам собирает строки одного события
auditd в одно событие, но только если они пришли в пределах «TTL буфера событий»
(по умолчанию 2 секунды). Поэтому строки одного события отправляйте **без паузы**:
режим «построчно», интервал `0`, разделитель `\n`.

### Постоянный поток событий

Включите цикл (`l`), задайте интервал и нажмите `Enter`. Задача будет работать в фоне,
пока вы не остановите её клавишей `s`. Одновременно можно запускать другие отправки.

### Отправка на несколько коллекторов сразу

Запустите задачу для первого коллектора, затем выберите второй и нажмите `Enter` ещё
раз. Задачи выполняются параллельно и не мешают друг другу.

## Если событие не дошло

Сначала посмотрите журнал: при ошибке в записи `ERR` есть подсказка.

| Что в журнале | Вероятная причина | Что проверить |
|---|---|---|
| `connection refused`, «порт закрыт» | на порту никто не слушает | запущен ли коллектор, верны ли порт и хост |
| `i/o timeout`, «нет ответа» | пакеты не доходят | файрвол, маршрутизация, VPN, правильность адреса |
| `no such host` | имя не разрешается | имя сервера, DNS; попробуйте IP-адрес |
| «сервер отвечает без TLS» | у коннектора TLS выключен | выключите TLS у коллектора в программе |
| «коллектор ждёт HTTPS», соединение разорвано | у коннектора TLS включён | включите TLS у коллектора в программе |
| `HTTP 404` | неверный путь | путь `/input` |
| «сертификат не прошёл проверку» | включена проверка самоподписанного сертификата | выключите «Проверять сертификат» |
| `WRN` с упоминанием ICMP (udp) | на udp-порту никто не слушает | запущен ли коллектор, верен ли порт |
| «не задан хост» | пусты и хост коллектора, и хост по умолчанию | клавиша `g` |
| «в источнике нет событий» | файл пуст или текст не введён | содержимое файла, режим |

Если в журнале `OK`, а события в KUMA нет:

1. **Разделитель.** Сравните его с полем «Разделитель» коннектора.
2. **UDP.** `OK` означает только то, что датаграмма отправлена. Проверьте адрес и порт,
   файрвол на сервере коллектора и между вами.
3. **Нормализатор.** Событие могло прийти, но не разобраться. Посмотрите метрики
   коллектора (счётчик входящих событий и ошибок нормализации) и включите у коннектора
   отладку.
4. **Режим.** Убедитесь по предпросмотру, что событие делится так, как вы ожидаете
   (например, многострочное событие не разошлось по строкам).

### Проверка без KUMA

Тестовый приёмник показывает, что и в каком виде приходит. Запустите его в отдельном окне:

```text
kuma_log_sender listen -p udp -P 5144
```

В программе создайте коллектор с хостом `127.0.0.1` и тем же портом и отправьте событие.
Приёмник напечатает каждое событие с экранированием служебных символов — видно, например,
есть ли в конце `\n` или `\x00`:

```text
10:15:02.102 #1 udp 127.0.0.1:53211 109 Б: "CEF:0|TESTVENDOR|TESTPRODUCT|1.1.1.1|TEST_EVENT|…"
```

Параметры: `-p tcp|udp|http`, `-P порт`, `-d` — разделитель (`\n`, `\t`, `\0`), `-tls` —
TLS с самоподписанным сертификатом, `-a 0.0.0.0` — принимать с других машин.

## Командная строка

Для скриптов есть режим без интерфейса.

```text
kuma_log_sender send -c ИМЯ (-f ФАЙЛ | -t ТЕКСТ) [-n N] [-i ИНТЕРВАЛ] [-m РЕЖИМ] [--loop]
```

| Параметр | Значение |
|---|---|
| `-c`, `--collector` | имя коллектора или его однозначная часть |
| `-f`, `--file` | путь к файлу или имя файла из папки `logs`; `-` — читать стандартный ввод |
| `-t`, `--text` | текст события |
| `-n`, `--count` | число повторов, по умолчанию 1 |
| `-i`, `--interval` | интервал, по умолчанию 1 секунда |
| `-m`, `--mode` | `lines` (построчно), `whole` (целиком), `delim` (по разделителю) |
| `--loop` | отправлять в цикле до `Ctrl+C` |

Результат каждой отправки печатается в консоль и пишется в `sender.log`. Код завершения:
`0` — всё отправлено, `1` — были ошибки или предупреждения, `2` — неверные параметры.

`kuma_log_sender list` выводит коллекторы с адресами и разделителями.

Общий параметр `--dir ПАПКА` (перед подкомандой) задаёт рабочую папку.

## Ограничения

- Режим TLS коннектора с аутентификацией клиента по сертификату («Нестандартный PFX
  с аутентификацией клиента») не поддерживается.
- Сжатие Snappy в коннекторе должно быть выключено.
- События отправляются в кодировке файла; перекодирование в отличную от UTF-8 кодировку
  не выполняется.
- Отправка в коннекторы других типов (kafka, nats, file и т. д.) не поддерживается.
