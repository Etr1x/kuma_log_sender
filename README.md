# KUMA Log Sender

> [!WARNING]
> Код этой утилиты написан ИИ. Он покрыт автоматическими тестами, но независимой проверки
> не проходил. Программа предоставляется «как есть», без каких-либо гарантий: вы используете
> её на свой страх и риск, и автор не несёт ответственности за возможные последствия
> (см. [лицензию](LICENSE)). Прежде чем применять её в рабочей среде, проверьте на тестовом
> стенде.

Утилита для отправки тестовых событий на коллекторы SIEM KUMA — чтобы проверять
нормализаторы и правила корреляции, не дожидаясь настоящих событий от источников.

Один исполняемый файл с консольным интерфейсом: выбираете коллектор, выбираете лог
(файл или текст), нажимаете `Enter`. Повторная отправка — ещё один `Enter`.

## Возможности

- **Коллекторы в отдельном файле** `collectors.json`; добавлять, менять и удалять их можно
  прямо в утилите.
- **Протоколы tcp, udp и http**, в том числе с TLS (tcp+tls, https). Для каждого коллектора
  задаётся разделитель событий, как в его коннекторе: `\n`, `\t`, `\0` или «нет».
- **Источник** — файл из папки `logs` (список обновляется сам) или текст, введённый либо
  вставленный в консоль.
- **Проигрывание файла построчно**: каждая строка уходит отдельным событием с разделителем
  коллектора. Многострочное событие можно отправить целиком.
- **Повторы и интервал**: отправить N раз с паузой (по умолчанию 1 секунда) или
  **в цикле**, пока не остановите.
- **Несколько отправок одновременно**: задачи работают в фоне, каждая со своим коллектором.
- **Журнал**: по каждой отправке видно, что, куда и сколько байт ушло, а если не ушло —
  почему, с подсказкой, что проверить. Всё дублируется в `sender.log`.
- **Ничего не нужно устанавливать**: один статически собранный файл без внешних
  зависимостей (ncat, curl, libssl и т. п. не требуются). Работает на Windows и Linux,
  в том числе без доступа в интернет.
- Горячие клавиши работают и в русской раскладке.
- Режим командной строки для скриптов и встроенный тестовый приёмник, чтобы проверить
  отправку без KUMA.

## Быстрый старт

1. Скачайте со страницы [релизов](https://github.com/Etr1x/kuma_log_sender/releases/latest)
   архив для своей системы (`kuma_log_sender_<версия>_windows_amd64.zip` или
   `..._linux_amd64.tar.gz`) и распакуйте его в любую папку.
2. Запустите `kuma_log_sender.exe` (в Linux — `./kuma_log_sender`). Окно терминала должно
   быть не меньше 80×20 символов.
3. Нажмите `g` и укажите **хост по умолчанию** — адрес сервера, на котором работают
   коллекторы.
4. Нажмите `a` и добавьте коллектор: имя, протокол, порт и разделитель — как у коннектора
   в KUMA. Готовый пример списка есть в `collectors.example.json`.
5. Положите файлы с логами в папку `logs` рядом с программой (вложенные папки тоже
   видны). Примеры лежат в `logs/examples`.
6. Выберите коллектор, клавишей `Tab` перейдите к списку файлов, выберите файл и нажмите
   `Enter`. В журнале появится результат каждой отправки.

Чтобы отправить строку из буфера обмена, просто вставьте её в окно программы: откроется
окно ручного ввода с этим текстом, `Enter` отправит его.

Подробности — в [инструкции по использованию](docs/USAGE.md).

## Основные клавиши

| Клавиша | Действие |
|---|---|
| `Enter` | отправить выбранный источник на выбранный коллектор |
| `Tab`, `Shift+Tab`, `←` `→` | переход между панелями |
| `↑` `↓`, `PgUp` `PgDn` | выбор в списке, прокрутка журнала |
| `/` | фильтр по имени в списке; `Esc` — сбросить |
| `i` | ручной ввод лога |
| `m` | режим: построчно / целиком / по разделителю |
| `c`, `+`, `-` | число повторов |
| `t` | интервал между отправками |
| `l` | цикл: отправлять, пока не остановят |
| `s` / `S` | остановить задачу / все задачи |
| `a` `e` `d` `y` | коллектор: добавить, изменить, удалить, создать копию |
| `g` | настройки: хост по умолчанию, таймаут |
| `?` | полная справка |
| `q` | выход |

## Файлы

Всё лежит в одной папке с программой, поэтому её можно переносить целиком.

| Файл | Назначение |
|---|---|
| `collectors.json` | коллекторы и общие настройки; создаётся при первом сохранении |
| `logs/` | файлы с логами для отправки |
| `sender.log` | журнал отправок (при 10 МБ переименовывается в `sender.log.1`) |
| `state.json` | что было выбрано при прошлом запуске |

Пример `collectors.json`:

```json
{
  "version": 1,
  "default_host": "kuma-collector.example.local",
  "timeout_sec": 5,
  "collectors": [
    { "name": "CEF TCP", "protocol": "tcp", "port": 5140, "delimiter": "\\n" },
    { "name": "Syslog-CEF UDP", "protocol": "udp", "port": 5144, "delimiter": "" },
    { "name": "KUMA Agent WEC", "protocol": "http", "port": 5365, "delimiter": "\\0", "tls": true, "path": "/input" },
    { "name": "Syslog на другом сервере", "protocol": "tcp", "host": "10.0.0.15", "port": 6514, "delimiter": "\\n", "tls": true }
  ]
}
```

Поле `host` у коллектора необязательно: если оно пустое, берётся `default_host`.
Файл можно править и вручную, после чего нажать в программе `r`. Разделитель при ручной
правке допустимо писать как в интерфейсе KUMA: `"\n"`, `"\t"`, `"\0"`.

Другую рабочую папку можно указать параметром `--dir` или переменной окружения
`KUMA_LOG_SENDER_HOME`.

## Командная строка

```text
kuma_log_sender send -c "Linux Auditd" -f auditd.log          # файл из logs построчно
kuma_log_sender send -c auditd -t "тестовое событие" -n 5 -i 0.5   # текст, 5 раз через 0,5 с
kuma_log_sender send -c wec -f event.xml -m whole              # многострочное событие целиком
kuma_log_sender send -c cef -f events.log --loop -i 2          # в цикле до Ctrl+C
kuma_log_sender list                                           # список коллекторов
```

Код завершения `0` — всё отправлено, `1` — были ошибки, `2` — неверные параметры.

### Тестовый приёмник

Чтобы убедиться, что события уходят, и увидеть их в точности такими, какими их получит
коллектор, можно запустить приёмник на своей машине и отправить события на `127.0.0.1`:

```text
kuma_log_sender listen -p udp -P 5144
kuma_log_sender listen -p tcp -P 5140 -d "\n"
kuma_log_sender listen -p http -P 5365 -tls -d "\0"
```

## Сборка из исходников

Нужен Go 1.26 или новее.

```text
go test ./...                 # тесты
go build -o kuma_log_sender.exe .
go run ./tools/bundle         # архивы для Windows и Linux в папке dist
```

Релиз выпускается автоматически: отправка тега вида `v1.2.3` запускает
[GitHub Actions](.github/workflows/release.yml) — тесты на Linux и Windows, сборку архивов
и публикацию их на странице релизов. Номер версии берётся из тега.

```text
git tag v1.2.3
git push origin v1.2.3
```

Чтобы собирать в контуре без интернета, выполните на машине с интернетом `go mod vendor`
и перенесите репозиторий вместе с папкой `vendor`.

Интерфейс построен на [Bubble Tea](https://github.com/charmbracelet/bubbletea).

Как проверять интерфейс в настоящем терминале (консоль Windows, tmux в Linux), описано
в [tools/e2e](tools/e2e/README.md).
