# Сквозная проверка в настоящем терминале

Модульные тесты (`go test ./...`) проверяют логику и раскладку экрана, но не работу
с реальным терминалом. Эти сценарии запускают собранную программу так, как её запускает
пользователь, шлют ей нажатия клавиш и сверяют экран и то, что получили локальные
приёмники (`kuma_log_sender listen`). KUMA для них не нужна.

## Windows

Нужен Python 3 (только стандартная библиотека).

```text
go build -o kuma_log_sender.exe .
python tools\e2e\windows_console.py kuma_log_sender.exe
```

Программа запускается в скрытой обычной консоли Windows (conhost); нажатия передаются
через `WriteConsoleInput`, экран читается через `ReadConsoleOutputCharacter`
(см. `condrv.py`). Проверяются запуск, отправка файла построчно и повтор, ручной ввод
и горячие клавиши в русской раскладке, вставка текста потоком нажатий, цикл и остановка,
сообщение об ошибке, форма коллектора, выход.

Размер скрытой консоли изменить нельзя, поэтому реакция на изменение размера окна в
Windows этим сценарием не проверяется.

## Linux

Нужен tmux. В Windows сценарий можно запустить в WSL.

```text
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o kuma_log_sender .
bash tools/e2e/linux_tmux.sh ./kuma_log_sender
```

Дополнительно проверяются командная строка (tcp, https, предупреждение об ICMP-отказе на
udp), вставка через bracketed paste и изменение размера окна.

Оба сценария создают временную рабочую папку и печатают её путь в конце; удалять её
нужно вручную.
